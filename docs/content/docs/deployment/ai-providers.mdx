# AI 模型接入

OpenDeepWiki 的每个 AI 任务都可以独立配置模型，按需混搭不同服务商：

| 任务 | 用途 | 环境变量前缀 |
|---|---|---|
| **聊天** | 对话式 AI 功能 | `CHAT_*`、`ENDPOINT` |
| **Wiki 目录** | 生成文档结构 | `WIKI_CATALOG_*` |
| **Wiki 内容** | 生成文档页面 | `WIKI_CONTENT_*` |
| **翻译**（可选） | 翻译文档，未配置时回退到内容生成配置 | `WIKI_TRANSLATION_*` |

两种配置方式：

- **环境变量**（本章）：部署时定死，适合单机与容器化部署
- **管理后台**（[AI Provider 与模型管理](/docs/admin-guide/ai-providers)）：运行时可视化增删改，支持多 Provider 多模型轮换，适合团队与生产

## 支持的提供商类型

通过 `*_REQUEST_TYPE` 变量指定：

| 类型 | 描述 |
|---|---|
| `OpenAI` | OpenAI API 和兼容端点（默认） |
| `AzureOpenAI` | Azure OpenAI 服务 |
| `OpenAIResponses` | OpenAI Responses API（禁用存储输出以兼容第三方端点） |
| `Anthropic` | Anthropic Claude API |
| `DeepSeekOpenAI` | DeepSeek OpenAI 兼容端点（含思考模式支持） |

## 各服务商配置示例

<Tabs groupId="provider">

<Tab value="OpenAI / 兼容端点">

适用于官方 OpenAI API 和任何 OpenAI 兼容服务（vLLM、Ollama、LiteLLM、OneAPI 等）：

```yaml title="compose.yaml"
environment:
  # 聊天
  - CHAT_API_KEY=sk-your-openai-key
  - ENDPOINT=https://api.openai.com/v1
  - CHAT_REQUEST_TYPE=OpenAI

  # Wiki 目录生成
  - WIKI_CATALOG_MODEL=gpt-4o
  - WIKI_CATALOG_ENDPOINT=https://api.openai.com/v1
  - WIKI_CATALOG_API_KEY=sk-your-openai-key
  - WIKI_CATALOG_REQUEST_TYPE=OpenAI

  # Wiki 内容生成
  - WIKI_CONTENT_MODEL=gpt-4o
  - WIKI_CONTENT_ENDPOINT=https://api.openai.com/v1
  - WIKI_CONTENT_API_KEY=sk-your-openai-key
  - WIKI_CONTENT_REQUEST_TYPE=OpenAI
```

</Tab>

<Tab value="Azure OpenAI">

```yaml title="compose.yaml"

  - WIKI_CONTENT_API_KEY=your-azure-api-key
```

## 翻译配置（可选）

不配置 `WIKI_TRANSLATION_*` 时自动回退到内容生成的模型。想让翻译走便宜模型可以单独指定：

```yaml
- WIKI_TRANSLATION_MODEL=deepseek-chat
- WIKI_TRANSLATION_ENDPOINT=https://api.deepseek.com/v1
- WIKI_TRANSLATION_API_KEY=sk-your-deepseek-key
- WIKI_TRANSLATION_REQUEST_TYPE=DeepSeekOpenAI
```

相关超时与重试参数（`WIKI_TRANSLATION_TIMEOUT_MINUTES` 等）见[环境变量大全](/docs/deployment/environment-variables)。

## 选型建议

| 场景 | 目录生成 | 内容生成 | 说明 |
| --- | --- | --- | --- |
| 追求质量 | 强推理模型（Claude/GPT 高端） | 强推理模型 | 大仓库结构复杂时差异明显 |
| 追求性价比 | 中端模型 | 中端模型 + 便宜模型翻译 | 目录质量决定整体结构，值得用好模型 |
| 本地离线 | Ollama (qwen2.5-coder 等) | 同左 | `ENDPOINT=http://host.docker.internal:11434/v1` |

<Callout type="info">
  Token 消耗与仓库大小、语言数量成正比。`WIKI_LANGUAGES` 每多一种语言，翻译成本线性增加；体验阶段建议只保留 `en,zh`。
</Callout>

## 验证 AI 链路

配置完成后：

1. 重启服务：`docker compose up -d`
2. 登录 → 添加一个小型仓库（建议先用几百个文件的仓库试水）
3. 在管理后台[仓库管理](/docs/admin-guide/repositories)观察处理日志，若目录生成卡住通常是 Key/Endpoint 不通
