# Docker Compose 部署详解

OpenDeepWiki 在项目根目录提供 `compose.yaml`，定义了两个服务：后端 API 和前端 Web 应用。PostgreSQL 用户可直接使用 `compose.pgsql.yaml`（见 [PostgreSQL 部署](/docs/deployment/postgresql)）。

## 服务架构

| 服务 | 容器端口 | 默认宿主机映射 | 描述 |
|---|---|---|---|
| `opendeepwiki` | `8080` | `8081:8080` | ASP.NET Core 后端 API + 后台 Worker |
| `web` | `3000` | `8090:3000` | Next.js 前端应用 |

> 端口映射以仓库中 `compose.yaml` 的实际内容为准，可按需修改。前端通过内部网络使用 `API_PROXY_URL=http://opendeepwiki:8080` 访问后端。

## 快速部署

<Steps>

<Step>

克隆仓库并进入目录：

```bash
git clone https://github.com/AIDotNet/OpenDeepWiki.git
cd OpenDeepWiki
```

</Step>

<Step>编辑 `compose.yaml` 中的环境变量（AI 配置与 JWT 密钥，[完整变量说明](/docs/deployment/environment-variables)）。</Step>

<Step>

启动所有服务：

```bash
docker compose up -d
```

在 `http://localhost:8090` 访问应用。

</Step>

</Steps>

## 完整 compose.yaml 参考

以下是当前 `compose.yaml` 的关键结构（完整内容以文件为准）：

```yaml
services:
  opendeepwiki:
    image: crpi-j9ha7sxwhatgtvj4.cn-shenzhen.personal.cr.aliyuncs.com/open-deepwiki/opendeepwiki
    build:
      context: .
      dockerfile: src/OpenDeepWiki/Dockerfile
    ports:
      - "8081:8080"
    restart: unless-stopped
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - URLS=http://+:8080

      # 数据库
      - Database__Type=${DB_TYPE:-sqlite}
      - ConnectionStrings__Default=${CONNECTION_STRING:-Data Source=/data/opendeepwiki.db}

      # JWT
      - JWT_SECRET_KEY=${JWT_SECRET_KEY:-OpenDeepWiki-Default-Secret-Key-Please-Change-In-Production-Environment-2024}

      # 仓库存储与本地目录导入白名单
      - REPOSITORIES_DIRECTORY=/data
      - RepositoryAnalyzer__AllowedLocalPathRoots__0=${LOCAL_IMPORT_ROOT:-/host/home/youruser}

      # AI 服务（聊天）
      - CHAT_API_KEY=${CHAT_API_KEY:-your-chat-api-key}
      - ENDPOINT=${ENDPOINT:-https://api.openai.com/v1}
      - CHAT_REQUEST_TYPE=${CHAT_REQUEST_TYPE:-OpenAI}

      # Wiki 目录生成
      - WIKI_CATALOG_MODEL=${WIKI_CATALOG_MODEL:-gpt-4o}
      - WIKI_CATALOG_ENDPOINT=${WIKI_CATALOG_ENDPOINT:-https://api.openai.com/v1}
      - WIKI_CATALOG_API_KEY=${WIKI_CATALOG_API_KEY:-your-catalog-api-key}
      - WIKI_CATALOG_REQUEST_TYPE=${WIKI_CATALOG_REQUEST_TYPE:-OpenAI}

      # Wiki 内容生成
      - WIKI_CONTENT_MODEL=${WIKI_CONTENT_MODEL:-gpt-4o}
      - WIKI_CONTENT_ENDPOINT=${WIKI_CONTENT_ENDPOINT:-https://api.openai.com/v1}
      - WIKI_CONTENT_API_KEY=${WIKI_CONTENT_API_KEY:-your-content-api-key}
      - WIKI_CONTENT_REQUEST_TYPE=${WIKI_CONTENT_REQUEST_TYPE:-OpenAI}

      # Wiki 翻译（可选，回退到内容配置）
      # - WIKI_TRANSLATION_MODEL=gpt-4o
      # - WIKI_TRANSLATION_ENDPOINT=https://api.openai.com/v1
      # - WIKI_TRANSLATION_API_KEY=your-api-key
      # - WIKI_TRANSLATION_REQUEST_TYPE=OpenAI

      # 并行生成数量 / 多语言支持
      - WIKI_PARALLEL_COUNT=${WIKI_PARALLEL_COUNT:-5}
      - WIKI_MAX_CONCURRENT_GENERATIONS=${WIKI_MAX_CONCURRENT_GENERATIONS:-1}
      - WIKI_LANGUAGES=${WIKI_LANGUAGES:-en,zh,zh-tw,ja,ko,es,fr,de,pt-br,pl,ru,ar}

      # Graphify 图谱产物（可选）
      - GRAPHIFY_BACKEND=${GRAPHIFY_BACKEND:-}
      - GRAPHIFY_MODEL=${GRAPHIFY_MODEL:-}
      - GRAPHIFY_OUTPUT_ROOT=/data/graphify-artifacts
      - GRAPHIFY_OPENAI_BASE_URL=${GRAPHIFY_OPENAI_BASE_URL:-}
      - GRAPHIFY_OPENAI_API_KEY=${GRAPHIFY_OPENAI_API_KEY:-}
    volumes:
      - ./data:/data

  web:
    image: crpi-j9ha7sxwhatgtvj4.cn-shenzhen.personal.cr.aliyuncs.com/open-deepwiki/opendeepwiki-web
    build:
      context: ./web
      dockerfile: Dockerfile
    ports:
      - "8090:3000"
    restart: unless-stopped
    environment:
      - NODE_ENV=production
      - SITE_URL=${SITE_URL:-http://localhost:8090}
      - API_PROXY_URL=http://opendeepwiki:8080
```

<Callout type="info">
  根目录提供 `.env.example`，可复制为 `.env` 后通过 `${VAR:-default}` 插值注入配置，无需直接修改 `compose.yaml`。
</Callout>

## 环境变量速查

### 必需变量

| 变量 | 描述 | 示例 |
|---|---|---|
| `JWT_SECRET_KEY` | JWT 签名密钥（生产环境必须更改） | 长随机字符串 |
| `CHAT_API_KEY` | 聊天 AI 服务的 API 密钥 | `sk-...` |
| `ENDPOINT` | 聊天 AI 服务端点 | `https://api.openai.com/v1` |
| `WIKI_CATALOG_API_KEY` | 目录生成的 API 密钥 | `sk-...` |
| `WIKI_CATALOG_ENDPOINT` | 目录生成端点 | `https://api.openai.com/v1` |
| `WIKI_CONTENT_API_KEY` | 内容生成的 API 密钥 | `sk-...` |
| `WIKI_CONTENT_ENDPOINT` | 内容生成端点 | `https://api.openai.com/v1` |

### 常用可选变量

| 变量 | 默认值 | 描述 |
|---|---|---|
| `DB_TYPE` | `sqlite` | 数据库类型：`sqlite` 或 `postgresql` |
| `CONNECTION_STRING` | `Data Source=/data/opendeepwiki.db` | 数据库连接字符串 |
| `WIKI_CATALOG_MODEL` | `gpt-4o` | 目录生成模型 |
| `WIKI_CONTENT_MODEL` | `gpt-4o` | 内容生成模型 |
| `CHAT_REQUEST_TYPE` | `OpenAI` | AI 提供商类型：`OpenAI`、`AzureOpenAI`、`OpenAIResponses`、`Anthropic`、`DeepSeekOpenAI` |
| `WIKI_PARALLEL_COUNT` | `5` | 并行 wiki 生成任务数 |
| `WIKI_MAX_CONCURRENT_GENERATIONS` | `1` | 集群同时生成的仓库 Wiki 数量，多实例共享 |
| `WIKI_LANGUAGES` | `en,zh,...`（12 种） | 支持的语言（逗号分隔） |
| `SITE_URL` | `http://localhost:8090` | 公开站点 URL，用于 sitemap、robots.txt 和 SEO 元数据 |
| `LOCAL_IMPORT_ROOT` | — | 允许导入的本地目录根路径（白名单） |
| `MCP_ENABLED` | `true` | 是否启用 MCP 端点 |
| `GRAPHIFY_*` 系列 | — | Graphify 图谱产物配置 |

完整变量表见 [环境变量大全](/docs/deployment/environment-variables)。

<Callout type="warn">
  在生产环境中始终更改 `JWT_SECRET_KEY`。默认密钥仅用于开发。
</Callout>

## 数据持久化

后端将所有数据存储在映射到 `./data` 的 Docker 卷中：

```yaml
volumes:
  - ./data:/data
```

此目录包含：

- SQLite 数据库文件（使用 SQLite 时）
- 用于分析的克隆仓库工作区
- Graphify 图谱产物等生成数据

<Callout type="warn">
  定期备份 `./data` 目录。它包含所有生成的文档和仓库数据。备份策略见[升级与备份](/docs/deployment/upgrade-backup)。
</Callout>

## 健康检查

后端内置健康检查端点 `/health`。`compose.pgsql.yaml` 中配置了健康检查与依赖顺序：

```yaml
healthcheck:
  test: ["CMD-SHELL", "curl -f http://localhost:8080/health || exit 1"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 15s
```

PostgreSQL 编排中，后端在数据库 `service_healthy` 后才启动。SQLite 默认编排未启用 `depends_on` 条件，前端启动失败时检查后端是否就绪即可。

## 构建镜像

```bash
# 构建所有镜像
docker compose build

# 为特定架构构建（通过 Makefile）
make build-arm   # ARM64：Apple Silicon、AWS Graviton
make build-amd   # AMD64：Intel/AMD x86_64

# 构建单个服务
docker compose build opendeepwiki   # 仅后端
docker compose build web            # 仅前端
```

## 常用运维命令

```bash
docker compose up -d                # 后台启动
docker compose logs -f              # 跟随查看全部日志
docker compose logs -f opendeepwiki # 只看后端日志
docker compose restart              # 重启服务
docker compose down                 # 停止服务（保留卷）
```

## 故障排除

### 后端启动失败

- 验证 AI API 密钥有效且端点可达
- 检查 `CONNECTION_STRING` 与你的数据库类型匹配
- 查看日志：`docker compose logs opendeepwiki`

### 前端显示连接错误

- 确保后端已启动：`docker compose ps`
- `API_PROXY_URL` 必须指向后端容器：`http://opendeepwiki:8080`

### 磁盘空间不足

- 克隆的仓库存储在 `./data` 中。通过 Web UI 或 API 清理不再需要的仓库
- 对于大型部署，考虑从 SQLite 切换到 [PostgreSQL](/docs/deployment/postgresql)

### 仓库克隆失败（私有仓库）

- 检查填写 Git 用户名与访问令牌（Token）而非登录密码
- GitHub Token 需要 `repo` 读权限；企业 Git 需确认网络可达
