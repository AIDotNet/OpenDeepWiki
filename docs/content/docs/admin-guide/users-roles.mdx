# 用户、角色与部门

## 用户管理

路径：**管理后台 → 用户管理**。支持搜索用户、按角色筛选：

![用户管理](/images/admin-users.png)

### 新增用户

<Steps>

<Step>点击右上角**新增用户**。</Step>

<Step>填写用户名、邮箱、初始密码，选择角色（User / Admin）与所属部门。</Step>

<Step>保存后把初始密码交给用户，用户可在[个人设置](/docs/getting-started/interface-tour)中修改。</Step>

</Steps>

### 其他操作

| 操作 | 说明 |
| --- | --- |
| 编辑 | 修改资料、重置密码、调整角色与部门 |
| 禁用/启用 | 禁用后该账号无法登录（Status 标记） |
| 删除 | 软删除账号；其创建的仓库归属关系建议先转移 |

<Callout type="warn">
  `IsSystem` 标记的系统内置管理员不可删除，防止锁死管理入口。
</Callout>

## 角色管理

路径：**管理后台 → 角色管理**。内置 `Admin` 与 `User` 两个角色：

![角色管理](/images/admin-roles.png)

- 角色决定用户能否进入 `/admin` 后台以及可用功能
- 可以创建自定义角色并分配给用户，满足"只读运维""部门管理员"等细分需求

## 部门管理

路径：**管理后台 → 部门管理**：

![部门管理](/images/admin-departments.png)

- 部门是树形结构，支持父子层级，对应公司/团队组织架构
- 用户可以归属到某个部门（在用户管理中设置）
- 仓库可标记为**部门持有**（`IsDepartmentOwned`），配合前台"机构目录"按组织浏览知识库

## 典型实践

| 场景 | 配置方式 |
| --- | --- |
| 团队知识库统一入口 | 建立部门树 → 用户归属部门 → 仓库设为部门持有 |
| 最小权限运维 | 创建只读角色，日常巡检用；管理员账号仅在变更时使用 |
| 外部协作者 | 单独建 User 账号，不授予 Admin，按需加入部门 |
