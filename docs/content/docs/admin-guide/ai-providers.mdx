# AI 服务商与模型管理

除部署时的环境变量（见 [AI 模型接入](/docs/deployment/ai-providers)）外，OpenDeepWiki 提供完整的运行时配置体系，全部在管理后台完成、**无需重启**：

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| AI 服务商 | 管理后台 → 工具配置 → AI 服务商 | 服务商接入：认证、端点、模型发现 |
| 模型管理 | 管理后台 → 工具配置 → 模型管理 | 模型档案：上下文、价格、能力 |
| 模型配置 | 管理后台 → 模型配置 | 任务路由：把系统任务绑定到 服务商+模型 |

## AI 服务商页

页面为**左右双栏工作台**：左侧是服务商卡片列表（按"已启用/已禁用"分组，支持搜索），右侧是选中服务商的配置面板。系统已内置一批常见厂商预设（OpenRouter、DeepSeek、Moonshot、通义、百度等），预设描述中带有官网与获取 Key 的链接。

![AI 服务商管理](/images/admin-ai-providers.png)

### 新增服务商

<Steps>

<Step>点击左栏顶部 **➕（新增服务商）**，弹出"新增自定义服务商"对话框。</Step>

<Step>填写三个字段：</Step>

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 服务商名称 | 是 | 全局唯一，如 `My OpenAI Proxy` |
| 协议类型 | 否 | 默认 OpenAI，见下表 |
| Base URL | 否 | 如 `https://api.example.com/v1`；创建后也可在右侧面板继续维护 |

<Step>点击**新增**。系统创建服务商壳（默认：认证方式 API Key、未启用、支持模型发现），随后在右侧面板继续配置。</Step>

</Steps>

**协议类型**共 5 种：

| 协议 | 界面说明 |
| --- | --- |
| OpenAI | OpenAI Chat 兼容，兼容 `/v1/chat/completions` |
| DeepSeekOpenAI | DeepSeek / MiMo OpenAI 兼容 Chat Completions |
| OpenAIResponses | OpenAI Responses API / 推理模型 |
| Anthropic | Claude / Messages API |
| AzureOpenAI | Azure 部署端点 |

### 配置服务商（右侧面板）

| 区域 | 字段/操作 | 说明 |
| --- | --- | --- |
| 基础 | API Key | 密码框，可切换明文；已有密钥时提示"留空表示保持原密钥，输入新值则覆盖" |
| 基础 | API 代理地址 | 自定义端点，用于代理或第三方兼容服务 |
| 基础 | 连通性检查 | 选择一个模型 → 点**检查**，立即验证 Key 与端点是否可用 |
| 高级 | 唯一名称 / 显示名称 | 内置服务商的唯一名称与协议不可改 |
| 高级 | 认证方式 | `API Key` / `OAuth` / `Channel` / `无需认证` |
| 高级 | 模型发现 Endpoint | 留空则使用 `Base URL + /models` |
| 高级 | 系统代理 URL / 图标 URL / 排序 / 描述 | 均可选 |
| 高级 | 启用模型发现 | 开启后可调用服务商模型列表接口，同步到模型管理 |
| 高级 | OAuth Config / Channel Config / Accounts / Request Overrides JSON | 高级账号令牌与请求覆盖（如 `{"headers":{"User-Agent":"..."}}`），普通场景留空 |

修改后点 **保存**；顶部开关控制该服务商**启用/禁用**。内置服务商不能删除，不使用时停用即可。

### 模型列表（服务商面板内）

- **获取模型列表**：调用服务商 `/models` 接口自动同步模型（提示"发现 N 个模型，新增 M 个"）
- **全部启用 / 全部禁用**：批量切换
- **➕ 新增模型**：手动登记（弹窗字段见下）
- 每行可单独启用/禁用、编辑

### 新增/编辑模型弹窗

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 模型 ID | 是 | 服务商的模型名，如 `gpt-4.1`、`deepseek-chat`（输入 `gpt-5+` 会自动切换协议为 OpenAI Responses） |
| 显示名称 | 否 | 留空取模型 ID |
| 模型类型 | 否 | 聊天 / 图像 / 语音 / 嵌入，默认聊天 |
| 协议类型 | 否 | 默认"继承服务商"，可单独指定 |
| 上下文窗口 / 最大输出 | 否 | Token 数 |
| 输入价格 / 输出价格 / 缓存命中价 / 缓存创建价 | 否 | 美元 / 1M tokens，用于成本统计 |
| 能力开关 | 否 | Tools（默认开）/ Vision / Thinking / JSON |
| 默认模型 / 启用 | 否 | 开关 |

## 模型管理页

路径：**管理后台 → 工具配置 → 模型管理**。跨服务商的模型档案中心：顶部 5 张统计卡（模型总数/启用/Thinking/Vision/已配置价格），支持按服务商、类型、关键词筛选。

![模型管理](/images/admin-models.png)

点击**新增模型**弹出与上文相同的模型表单；卡片上可直接编辑、删除（需确认）。

## 模型配置页（任务路由）

路径：**管理后台 → 模型配置**。把系统流程绑定到"服务商 + 模型"组合：

![模型配置](/images/admin-model-configs.png)

**系统任务绑定**（核心流程，各绑定一行，可独立保存或"保存全部"）：

| 任务 | 说明 |
| --- | --- |
| 目录模型（WIKI_CATALOG） | 生成文档结构和导航树，快速低成本模型即可胜任 |
| 内容模型（WIKI_CONTENT） | 生成包含代码分析的实际文档内容，建议用最强模型 |
| 翻译模型（WIKI_TRANSLATION） | 翻译已生成文档，快速低成本模型即可 |
| Graphify 模型 | 知识图谱产物生成 |

每个绑定显示服务商的 API Key 配置状态（已配置/未配置）与模型元数据（上下文、最大输出、价格、能力标记）。未完成的绑定标记"等待绑定"。

**通用业务模型配置**：面向 Chat Assistant、MCP、嵌入应用等场景的可复用绑定，字段为配置名称 / 服务商 / 模型 / 状态 / 默认 / 描述。

<Callout type="info">
  模型配置页的绑定优先级**高于**环境变量。绑定后，环境变量中的 `WIKI_CATALOG_*`、`WIKI_CONTENT_*` 等模型配置不再生效；系统设置页中这些键也已隐藏并提示"请在模型配置中修改"。
</Callout>

## 系统设置里的"快速设置"向导

路径：**管理后台 → 系统设置**，页面顶部提供**供应商快速设置**向导，最快的三步配置：

<Steps>

<Step>选择供应商 → 输入 API 密钥 → 点**加载模型**（自动发现可用模型）。</Step>

<Step>分别为目录模型、内容模型、翻译模型选择模型（页面给出了各任务的选型建议）。</Step>

<Step>点**应用配置**，一键完成服务商录入 + 模型同步 + 三任务绑定。</Step>

</Steps>

新实例推荐先用这个向导跑通，再到各管理页细调。

## 验证与排障

| 现象 | 处理 |
| --- | --- |
| 连通性检查失败 | 核对 Key、Base URL；内网服务确认容器可达（本机用 `host.docker.internal`） |
| 获取模型列表失败 | 检查"模型发现 Endpoint"与"启用模型发现"开关 |
| 绑定后生成仍走旧模型 | 模型配置页绑定未保存，或存在多个"默认"标记 |
| 服务商名称重复提示 | 换一个唯一名称 |
